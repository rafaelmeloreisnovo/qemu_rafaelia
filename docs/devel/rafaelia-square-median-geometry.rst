RAFAELIA median-contact square kernel
======================================

Status
------

This document specifies a bounded proof of concept for executing one exact
geometric kernel under the i386 and x86_64 QEMU linux-user targets.  It does
not claim a full-system guest boot, performance superiority, physical memory
recovery, or a scientific result beyond the stated algebraic invariants.

Canonical operators
-------------------

Let ``R(theta)`` denote the planar rotation matrix.  The two median-contact
operators are

::

   T+ = 2^(-1/2) R(+pi/4) = 1/2 [[ 1, -1], [ 1, 1]]
   T- = 2^(-1/2) R(-pi/4) = 1/2 [[ 1,  1], [-1, 1]]

For a square centred at the origin with vertices ``(+/-a,+/-a)``, either
operator maps the four vertices to ``(+/-a,0)`` and ``(0,+/-a)``.  Therefore
the transformed square is rotated by 45 degrees, its vertices stop at the
side midpoints of the previous square, and its linear scale is
``q = 1/sqrt(2)``.

Exact invariants
----------------

The implementation verifies the following identities without floating point:

::

   T+^T T+ = T-^T T- = (1/2) I
   det(T+) = det(T-) = 1/2
   T+ T- = T- T+ = (1/2) I
   T-^4 = -(1/4) I
   T-^8 =  (1/16) I

Consequently, for iteration ``n``:

::

   side_n      = side_0 * 2^(-n/2)
   perimeter_n = perimeter_0 * 2^(-n/2)
   area_n      = area_0 * 2^(-n)
   radius_n^2  = radius_0^2 * 2^(-n)

If a three-dimensional object is generated by a similarity transformation
with the same linear factor, its volume follows
``volume_n = volume_0 * 2^(-3n/2)``.  This final statement is conditional on
the chosen 3-D construction; it is not inferred from planar rotation alone.

Circle chain
------------

For a square of side ``s``, the circumradius and inradius are
``R=s/sqrt(2)`` and ``r=s/2``.  The next median-contact square has side
``s/sqrt(2)`` and circumradius

::

   R_next = (s/sqrt(2))/sqrt(2) = s/2 = r.

Thus the circumcircle of each inner square is exactly the incircle of the
preceding square.  The internal and external circles are not decorative
approximations; they are linked by the recursive construction.

TCG integration
---------------

``tests/tcg/multiarch/rafaelia-square-median.c`` is intentionally plain C.
The existing multiarch makefile discovers every ``*.c`` file in that
directory, so the test enters the normal TCG target lists.  Its return codes
are fail-closed:

::

   0  all exact invariants passed
   1  midpoint contact failed
   2  norm/area progression failed
   3  opposite-rotation composition failed
   4  eight-step orientation cycle failed
   5  determinant/area scaling failed
   90 unsupported pointer width

``tests/rafaelia/geometry_x3264_reference.py`` provides an independent exact
``Fraction`` model and bounded signed-width simulations for 32 and 64 bits.

Evidence boundary
-----------------

A successful native build proves source and ABI compatibility only.  A
successful run through source-built ``qemu-i386`` and ``qemu-x86_64`` proves
the bounded linux-user execution represented by this test.  It still does
not prove:

* full-system x86 guest boot;
* Android/Vectras dispatch;
* correctness of unrelated QEMU subsystems;
* physical error correction or bit recovery;
* performance superiority;
* a general law for arbitrary geometric or physical systems.

Until the workflow yields observable steps and sealed artifacts,
``qemu_i386_runtime`` and ``qemu_x86_64_runtime`` remain ``TOKEN_VAZIO`` and
``claim_allowed`` remains ``false``.
